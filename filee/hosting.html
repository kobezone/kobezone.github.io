部署说明

这个目录把 KnifeLemon/Filee 发布到 GitHub Pages 的 /filee/。

怎么打开

  • 线上（合并到 master 之后）：https://kobezone.github.io/filee/
  • 简体文档：index.html
  • 英文文档：README.html
  • 全部页面：文档目录
  • 界面原型：docs/design/mockup.html。可以在浏览器里把格式拖到圆环上、调整顺序、编辑预设。
  • 桌面安装包：GitHub Releases。本目录不放 exe、dmg 和压缩包。

本地预览

在本仓库根目录启动静态服务，然后打开 http://127.0.0.1:8765/filee/。

python3 -m http.server 8765

构建方式

仓库用 .NET 构建桌面程序（Filee.slnx，dotnet run --project src/Filee.App）。根目录没有 package.json，发行附件是各系统安装包。可以在浏览器里直接打开的上游页面是 docs/design/mockup.html。

本目录发布各语言 README 和 docs/ 的 HTML、截图、docs/themes 示例、许可证和界面原型。C# 源码、测试和安装脚本留在上游该 commit；文档里指向源码的链接打开 GitHub 上的对应文件。被 README 链接到的 installer/linux/INSTALL.txt 会一并放进本目录。

子路径 /filee/

文档页是多页 HTML，站内地址使用相对路径，例如 docs/media/banner-zh-CN.jpg 和 ../site.css。页面放在 /filee/ 时，浏览器向这个子路径请求资源。这里没有单页应用的路由 base，也没有把资源写成站点根路径 /assets/...。

标识 HTQGP2E

这次部署收到的口令是 HTQGP2E。在上游 ccac2a57 的 README、配置和构建脚本里查找过访问码、房间码和构建参数，没有这个值，构建命令也不接收它。

打开 /filee/ 直接进入文档，页面上没有输入框。HTQGP2E 记在本页和 snapshot.json 的 accessCode 字段，用来和这次部署对照。

重新生成

脚本在 tools/render.mjs。准备好上游检出，并安装 marked@15 和 github-slugger@2 后运行：

FILEE_SRC=/path/to/Filee FILEE_OUT=/path/to/filee node filee/tools/render.mjs

本站的 cook/ 和 laotoule/ 不在这次发布的范围内。
